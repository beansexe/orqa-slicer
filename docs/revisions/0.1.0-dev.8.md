# Revision 0.1.0-dev.8 — cloud restriction explanation and temperature display

Status: needs user testing.

The Bambu network plug-in's `unsigned_studio` rejection now explains that sign-in,
status, and light control do not imply authorization for every command. It directs
cloud users to Bambu Studio or Bambu Handy for restricted changes, including loaded
filament editing, instead of instructing them to switch to LAN and Developer mode.
This revision does not unlock restricted commands or replace the networking plug-in.
The original upstream message remains when dual-vendor integration is disabled.

Flashforge temperatures now use an explicit Unicode degree symbol, avoiding the
extra `Â` visible in the user's screenshot.

## Quick user checks

Close the running preview and open Launch-Slicer.cmd. The launcher uses revision
1's existing settings and sign-ins. No new ZIP or account migration is required.

- Check that Flashforge temperatures show °C correctly.
- If a Bambu command is rejected, check that the message explains the cloud route.
  Change loaded filament in Bambu Studio or Handy, then refresh status in this build.
- Firmware update availability remains unverified until a real update is offered.
  “No update notice received” means no explicit availability signal was received;
  it is not proof that the installed firmware is the newest release.

Revision 7 remains available through Manage-Versions.cmd. Revision 6 has the user's
confirmed Flashforge cloud job submission. All revisions share the original
settings folder; switching versions changes the program, not account data.

## Evidence and limits

October 15 user reports confirm Bambu cloud light toggling, and Flashforge live
completed status, 100% progress, current firmware 5.1.8-2.2.3 and the update row.
Bambu loaded-filament editing triggers the network plug-in restriction. No real
available-firmware announcement has been confirmed.

Bambu's official authorization documentation lists AMS settings among protected
operations and explicitly distinguishes status/LED access from restricted control:
https://blog.bambulab.com/firmware-update-introducing-new-authorization-control-system-2/

A community replacement claims cloud printing, camera and AMS synchronization:
https://github.com/persano/open-bambu-networking-plugin
Those claims do not verify loaded-filament editing or compatibility with X2D/H2S.
It has not been installed or included in this build. A replacement needs a separate
compatibility and rollback review before changing the user's working connection.

Validation for this small UI change is limited to changed-source checks, fresh
patch reproduction, native Release build/install and package/runtime checks. No
printer commands, sign-ins, firmware installation or broad test suites are run.
