# 0.1.0-dev.12 — SolidWorks export and print bridge

Based on revision 11, retaining Multi-print and the repaired vendor connections.

Adds a SolidWorks CommandManager add-in with live printer, nozzle, material and
process choices, including unsaved process/filament settings. STEP export uses
the active configuration, replaces the same temporary export, and can load into
Orca for editing or slice in a separate background process.

Background Print is initially limited to one material/one extruder on an external
spool. AMS and multiple extruders use Load in slicer and native print review.
Orca must already be running. The native bridge never exports account secrets.
Temporary session data is removed on normal shutdown; lost responses are not
retried. Existing source imports are replaced by stable object identity.

The CLI gains high-quality STEP import and vendor catalog-ID lookup for sliced
archives, required for native archive validation before cloud submission.

See [the workflow](../solidworks-workflow.md) and the matching user checklist.
This revision requires user acceptance testing; hardware printing is not exercised
during development.

Validation: native Release build/install completed; C# add-in compiles against
the installed SolidWorks 2026 API assemblies; all 13 mailbox/argument checks pass.
A real hidden CLI run imports the STEP fixture, orients/arranges/slices it and
exports a 3MF with G-code and preview. The production archive inspector accepts
its actual catalog ID/nozzle/plate/PNG and rejects a mismatched nozzle. The
reproducible native integration patch passes its reverse applicability check.
Windows COM and type-library registration completed. The add-in loaded into the
running SolidWorks 2026 session with part commands enabled; the active document's
identity and unsaved flag were preserved. Actual CAD export, unsaved-edit round
trips and hardware print delivery remain user acceptance tests.

The running revision's real bridge also passed local protocol/session checks
and discovered three connected printers. Their matching profiles supplied
100/103/100 compatible material choices and 10/8/7 process choices, respectively;
all three produced resolved, temporary machine/process/filament snapshots without
network credential fields. No model was loaded and no print was submitted.
