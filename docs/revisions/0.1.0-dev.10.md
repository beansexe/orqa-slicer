# Revision 0.1.0-dev.10 — optional Bambu Community Cloud

Status: needs user testing. Standard Bambu remains the default connection.

This milestone adds a separately packaged, source-built networking and camera
backend based on Open Bamboo Networking. The normal Device page and printer
controls use the selected backend. It is intended to provide a cloud route for
controls the vendor plug-in restricts, and an alternative cloud camera path.
Actual acceptance on X2D, X1C and H2S has not been tested by development tools.

## Enable and test

1. Close the running preview and open Launch-Slicer.cmd. Open Printer accounts.
2. Under Bambu, click **Cloud connection options…**, accept Community Cloud,
   then close and reopen the slicer. The choice is saved for this revision.
3. Open Printer accounts again. Confirm **Connection: Community Cloud
   (experimental)**. Sign in to Bambu using the normal Bambu account dialog.
   This backend has its own session, so the standard session does not transfer.
4. Select a Bambu printer and check status/AMS data, loaded-filament editing,
   a small deliberate movement when the printer is idle, and camera playback.
   Test cloud printing on a suitable plate when ready. Confirm each operation on
   the printer; a signed-in label or transport success is not full validation.
5. Check Flashforge still signs in, reports status and sends/controls cloud jobs.
   Its Adventurer 5M nozzle values now follow the vendor's correct temperature
   fields. The delayed bed values remain under investigation.

No LAN or Developer mode is required by this backend build. Printer LAN MQTT
connection attempts are disabled. Camera minting uses the cloud route without
the upstream LAN fallback. Cloud camera streaming may use peer-to-peer transport
negotiated through the cloud; cloud mode does not mean every video packet passes
through a relay server. No Windows-wide camera registration is changed.

## Return to the standard connection

Open Cloud connection options again, choose the standard connection and restart.
If startup fails, use Manage-Versions.cmd to select revision 9. Alternatively,
delete only `bambu-backend.txt` from revision 10's program folder while it is
closed; absent or invalid choice files select the standard connection.

The backend choice is frozen for the running process: changing it cannot combine
one backend's networking DLL with another backend's camera DLL. Missing Community
Cloud files cause a load failure, not a silent switch to another plug-in. The
existing downloaded Bambu and installed Flashforge plug-ins are not overwritten.

## Accounts, source and limits

Existing slicer settings still come from revision 1 through the launcher.
Community Cloud keeps separate state in its `orqa-community` subfolder. Windows
DPAPI protects the community account session for the current Windows user. Session
files are not portable to another Windows account or machine. No credentials are
copied from standard Bambu, Flashforge, or Bambu Studio. Diagnostic file/stderr
logging is disabled in this build; TLS certificate validation remains enabled.

The community library is independent of Bambu Lab and is not vendor-approved.
Its interoperability implementation includes a Studio-compatible client identity,
attestation metadata and shared app-certificate bootstrap logic. It does not make
this slicer an officially authorized Bambu client. Vendor changes can break the
connection, and this build does not guarantee full Studio feature parity. Hardware
acceptance of restricted commands, camera support and account sign-in remain
user-test items. No account sign-in, real print/control operation or firmware
installation has been performed by development tools.

Background camera/certificate tasks are owned and drained before agent destruction.
The library uses the slicer's native camera tunnel interface; it does not register
a system-wide DirectShow filter or replace the standard live555 DLL.

Pinned source: https://github.com/persano/open-bamboo-networking/tree/da9d91f530dd20b3d6cc19d18178914d9c651b75

Local build changes and source lock are in `integration/community`; the reusable
build entry point is `scripts/build-community-bambu.ps1`. The package contains
source and notices alongside the optional DLLs. Later local builds reuse cached
source and dependency output; no full slicer ZIP download is needed.

Development checks focus on compilation/packaging, parameter ABI compatibility,
required DLL exports, an empty-profile agent lifecycle, protected-session data and
shutdown ownership. Visual and real-printer behavior are left for user testing.
