# 0.1.0-dev.4 — Flashforge cloud status and sending

Status: **needs testing**. This revision connects the Flashforge account to live
device queries and cloud job submission. Real cloud operation and printing have
not been tested by the development session.

Close the current preview, then open **Launch-Slicer.cmd**. The launcher reuses
0.1.0-dev.1's settings, sign-ins, and presets. Keep that revision's data_dir in
place. Do not run two previews with those settings at once. Manage-Versions.cmd
retains revision 3 for executable rollback; settings remain shared.

1. Open **Printer accounts** and wait for Flashforge restoration. Open the
   **Flashforge** tab and select the Adventurer 5M.
2. Check **Monitor selected printer through Flashforge Cloud**. While this page
   is visible, it requests device status about every five seconds when no other
   account operation is running. Check device status, nozzle and bed values,
   progress, firmware, and the update age against the printer. The list status
   and its refresh age remain separate from these device queries. Stealth Mode
   must be off. Camera playback and firmware update announcements are deferred.
3. Use **Choose printer…** to select that machine and its installed nozzle
   profile. Prepare and slice a small, single-material plate, then open Preview.
4. Return to Flashforge and click **Send current plate via cloud…**. Confirm the
   machine, nozzle, and plate. **Start printing after delivery** starts unchecked:
   leave it unchecked for the first file-delivery test. Confirm with **Send via
   cloud** only when ready to send. Merely selecting a printer never submits a job.
5. Check the result and any cloud job ID, then check the printer's file list.
   A successful transport result is not proof that the printer executed a job.
   For a later physical test, enable Start printing after delivery explicitly;
   bed leveling and time-lapse are optional controls in the same dialog.
6. Switch back to a Bambu profile and Device. Confirm its live status still works.

Cloud sending refreshes the account list and device status first, checks that the
printer is ready and belongs to the current account, verifies the profile and
exported sliced plate, then uploads, creates the cloud job, and submits its command.
This preview supports one nozzle and one used filament. It requires the installed
Flashforge networking plugin's cloud functions; the plugin is not redistributed.
No LAN address is needed for this cloud path. Existing native LAN setup remains
available as a fallback.

**Cancel sending** requests cancellation of the pending upload/send operation; it
does not stop an already delivered print. A timed-out or uncertain result may have
reached the printer. Check the printer and any displayed job ID before manually
trying again. The application does not automatically retry a print command.

Optimized account/status, archive fixture, cloud workflow, and connection lifecycle
tests use simulated responses and temporary files, without your account or printer.
Native build, source checks, and package checks are recorded in
BUILD-VERIFICATION.json. Proprietary plugin callback behavior and real cloud
acceptance remain part of this revision's user testing. No physical print, firmware
installation, or real cloud upload was performed during development.
