# Revision 0.1.0-dev.11 — Multi-print workspace

Status: built and published locally; needs user printer testing.

Multi-print is a visible toggle beside Slice/Print. Enabling it opens the
printer-card pane on the left of Prepare/Preview and defaults the main Print
action to Print to all printers. The dropdown includes the same action.

A card assigns one source plate to one account printer, with an exact printer /
nozzle profile. Add another printer for the same source plate to print its
objects on another brand or model. A printer cannot be added twice for the same
source plate. Multiple source plates can have their own printer assignments.

Click a card to restore its printer, process and filament configuration into
Orca's normal controls. Changes are captured when switching or running a batch.
Per-plate options are captured too. Source objects and per-object edits remain
shared. Slices are invalidated when switching cards, so a printer never reuses
another printer's toolpath. Current status is not a permanent compatibility
certificate: changes are validated and sliced again before each send.

Print to all printers works through cards sequentially. Each card gets native
size/settings/material validation and its own slice. Invalid cards are marked
and skipped. Each valid card opens its vendor's send dialog for review and AMS
mapping. Flashforge defaults Start printing after delivery on in this batch
flow; its ordinary Device send flow retains the previous unchecked default.
The batch waits for the Flashforge cloud worker before continuing. Native Bambu
send dialogs own their delivery results; the card says review complete rather
than claiming a job was accepted merely because the dialog closed.

Cancel stops remaining cards. It does not stop an active send or prints already
started. There are no automatic print retries and no added LAN fallback.

Save Multi-print workspace writes a standard source .3mf and a neighboring
.3mf.multi-print.json file containing printer identities and secure settings
snapshots. Account tokens/passwords are not included in the card format. Keep
both files together. Reopen the 3MF with normal File/Open, enable Multi-print,
and load its printer cards. The companion project checksum must match; malformed
settings, missing plates, duplicate targets and oversized files are rejected.
This two-file workflow keeps ordinary 3MF project compatibility unchanged.

The build includes the user-confirmed X2D cloud-print authentication repair,
independent Bambu and Flashforge accounts, and existing cloud Device workflows.
Video, homing and cloud printing on X2D were confirmed by the user on revision
10. Multi-print itself is new and has not been tested on actual printers.

Known first-build boundaries: slicing/sends run sequentially; each vendor send
confirmation remains; each card's toolpath is generated when selected/sent,
not cached for immediate switching between previews. Printer cards are saved
explicitly alongside a standard 3MF rather than embedded in its file format.
