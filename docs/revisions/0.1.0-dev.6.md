# 0.1.0-dev.6 — Match the exported printer model and identify preparation failures

Status: **needs testing**.

This fixes a cloud-send verification bug after the confirmation dialog. Orca's
exporter writes the printer's internal catalog ID (Flashforge-Adventurer-5M),
while the send bridge previously expected the profile's display name. The bridge
now obtains the same catalog ID through the same preset method as the exporter.
The confirmation dialog continues to show the readable model name.

Preparation errors now identify the failing step: temporary files, plate export,
preview image, unreadable archive/settings/G-code, model/nozzle mismatch, or files
changing during verification. Raw file contents, paths, SDK responses, and account
credentials are not included in these errors. Verification remains required before
cloud submission.

Close the current preview and open Launch-Slicer.cmd. Open Printer accounts once
and wait for Flashforge restoration. Select the correct printer/nozzle profile,
slice the same single-material plate, and open Preview. Use Send current plate
via cloud and confirm with Start printing after delivery unchecked for the first
test. Check the resulting message/job ID and the printer's file list. If preparation
still fails, report the new, specific error. Camera and firmware updates are deferred.

The catalog-ID regression, valid sliced-file fixture, 14 malformed/mutation cases,
and stage-diagnostic checks pass without contacting an account or printer. Fixtures
read the ID from the pinned Flashforge profile definition. Real GUI export/cloud
delivery and physical printing still need user validation. Revision 5's material
fix remains included; earlier revisions remain available for executable rollback.
The launcher reuses revision 1's original settings folder and saved sign-ins.
