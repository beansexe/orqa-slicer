# 0.1.0-dev.2 — Bambu session and connection status

Status: **needs testing**. This revision addresses the reported restart mismatch:
the account dialog was signed in, the homepage was signed out, and selecting a
listed Bambu printer reported a server connection failure.

Bambu's homepage status now comes from the same native session state as Printer
accounts. It no longer depends on the networking plugin's opaque login-configuration
message, and a Bambu status poll does not log the account out. The account dialog
shows cloud connected/disconnected separately from signed-in status.

Startup restores each registered signed-in cloud account independently of the
selected printer profile. Its existing login handler connects that provider only.
Only the active printer provider refreshes DeviceManager's single live device
list, so a background account refresh cannot invalidate its pending response.
Previously, starting with a Flashforge/generic profile could leave a restored
Bambu session without starting its live cloud connection. Stealth mode still
prevents cloud restoration. Numeric connection return/reason codes are recorded
without account identities, tokens, or payloads in the added diagnostics.

This revision reuses 0.1.0-dev.1's settings through `--datadir`; no settings or
credentials are copied. Keep that older revision's data_dir in place. Close the
currently running preview before opening Launch-Slicer.cmd so both versions do
not use the same settings simultaneously. Use the workspace launcher or
Manage-Versions.cmd; opening the new revision's executable directly bypasses this
settings reference and uses its separate empty settings folder. The older
executable remains available for rollback through Manage-Versions.cmd. Both
revisions share subsequent account and preset changes; rollback changes the
executable without restoring an earlier settings state.

Focused Release tests and pinned clang-tidy checks cover Bambu status messages,
restored Bambu without Orca sign-in, independent providers, and stealth mode.
Manager tests cover settings references and launch arguments using synthetic
fixtures. Full build and runtime check results are recorded in the checkpoint.

User checks:

1. Launch the selected revision after closing the previous preview. Both
   accounts should be available without another sign-in.
2. Compare the Bambu homepage row with Printer accounts. The account session
   labels should agree; cloud connectivity is a separate status in the dialog.
3. Start with a Flashforge profile, close and reopen the app, then select a Bambu
   profile and the H2S in Device. Check live temperatures/status and the server
   banner. No print is required for this connection test.
4. Confirm Flashforge still restores and lists the Adventurer 5M.

The source gap is fixed; actual Bambu broker connectivity still needs the user's
restart test. This revision does not add Flashforge cloud job submission,
the unified printer picker, or firmware notifications.
