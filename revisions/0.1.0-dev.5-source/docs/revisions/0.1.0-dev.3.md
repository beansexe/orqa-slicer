# 0.1.0-dev.3 — Flashforge device access and printer selection

Status: **needs testing**. This revision adds a Flashforge page and connects the
prepared printer chooser to the native application.

- **Flashforge** in the top row opens the account's printer list. Select a
  printer to see its model, last reported account status, and list refresh age.
  **Refresh printer list** runs without blocking the page. The page clearly
  identifies these as account-reported values; live temperatures, progress,
  camera, and printer controls are not available there yet.
- **Printer accounts → select a Flashforge printer → Open device** opens that
  printer on the Flashforge page. Double-clicking the account-list row does the
  same thing. After restarting the app, open Printer accounts once to restore
  the remembered Flashforge session before using this page's refresh button.
- **Choose printer…** in the main menu lists available Bambu and Flashforge
  account printers and their matching enabled nozzle profiles. It checks the
  actual resulting profile after any unsaved-settings prompt. **Add printer
  profiles…** opens Orca's normal printer setup wizard if the needed profile is
  missing. Reopen the chooser after changing enabled profiles.
- Selecting a Bambu printer uses Orca's existing selection and opens Device.
  Selecting Flashforge opens its page. **Set up Flashforge LAN printing…**
  opens Orca's existing Connection settings. Choose the Flashforge host type,
  then discover the printer or enter the address, serial number and
  checkCode/API key requested by that dialog. Use details from the printer's
  network settings. No print starts when choosing a printer or opening setup.

The Flashforge page does not submit cloud jobs. Existing native LAN printing
remains available through the Connection setup and normal slicing/send workflow;
its operation with the Adventurer 5M still needs testing. Bambu video is unchanged
and remains deferred, following the user's successful live-status report.

This revision uses 0.1.0-dev.1's original settings directory through the workspace
launcher. Close the current preview, then open Launch-Slicer.cmd. Keep the original
settings folder in place. Directly opening the new executable bypasses the saved
settings reference. Rollback through Manage-Versions.cmd changes the executable;
all builds using that folder share subsequent account and preset changes.

First checks:

1. Open Printer accounts and wait for Flashforge restoration. Select the
   Adventurer 5M and click Open device. Its name/model/account status should
   appear on the Flashforge page. Refresh and check the refresh age/message.
2. Use Choose printer to select its exact enabled nozzle profile. Check the
   selected profile in Prepare. If none matches, use Add printer profiles,
   enable the correct Flashforge machine/nozzle, and reopen the chooser.
3. Open Flashforge LAN setup and confirm the normal Connection dialog appears.
   A physical print is not required for this navigation check.
4. Return to a Bambu profile and printer. Device should still show live status.
   If its list is initially unavailable, select a Bambu profile in Prepare and
   open Device once to populate Orca's native list, then reopen the chooser.
5. Verify that signing out of Flashforge clears its device view while Bambu
   remains signed in. Restore Flashforge afterward if desired.

Build, source-check and runtime results are recorded in BUILD-VERIFICATION.json
inside the published revision. Interactive account, profile, and printer checks
remain user tests until explicitly confirmed.

User screenshots subsequently confirmed the Flashforge page with recent
account-reported status, all four requested machine models in the chooser, and
Adventurer 5M nozzle choices. A follow-up confirms that committing the nozzle
profile updates Prepare. Wireless operation is still unconfirmed; see
0.1.0-dev.3-user-tests.md for the exact test scope.
