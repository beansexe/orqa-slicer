# 0.1.0-dev.1 — accounts

Status: **needs testing**. This revision is the first native account integration
preview. Development of later revisions continues with this interface as its
baseline; the remaining session and printer checks still require validation.

On October 14, 2026, the user reported successfully signing into both the Bambu
and Flashforge accounts. This confirms the reported sign-in outcome, rather than
the full account test suite. The authentication method, session restoration,
printer-list correctness, logout isolation, and printing were not reported.

The Printer accounts menu adds independent Bambu Lab and Flashforge controls.
Bambu uses Orca's existing networking provider. Flashforge uses the compatible
networking plugin in the existing Orca-Flashforge installation, keeps its own
session, and displays its cloud printer list. Remembered Flashforge sessions use
the system credential store; passwords are not saved.

The local version manager selects a complete portable revision and retains older
revisions for rollback. Launch-Slicer.cmd opens the selected revision. Source
changes and build instructions are included under revision-source. There is no
need to redownload the source ZIP for local iteration.

Verification completed before packaging: native Release build and installation,
CLI help exit code 0, bundled Python runtime imports, and GUI startup to the
first-run welcome page using an isolated settings directory. Also completed:
native dependency build, account adapter
simulation tests, installed plugin initialization without sign-in, and the pinned
clang-tidy checks. Focused tests cover remembered-session write failures and
safe restoration disablement during sign-out. The account dialog's visual layout
has not yet been checked after first-run setup. Compilation and startup checks
do not establish real account sign-in, session persistence, or printer operation.

User checks still required:

1. Reopen Printer accounts and check that both accounts remain signed in together.
2. Check that the Flashforge printer list matches the account.
3. With remembered sign-in enabled, reopen the dialog, then restart the
   application and open Printer accounts again. Flashforge restoration starts
   when this dialog opens, rather than in the background at application startup.
4. Sign out of one provider and verify that the other remains signed in.
5. Check offline startup and offline Flashforge sign-out. Once online, reopen
   Printer accounts to retry a remembered session that could not reconnect.
6. Exercise Bambu printer selection, settings, slicing, and a supervised wireless
   test job using an appropriate model and profile.

Also check session-only Flashforge sign-in: uncheck Keep me signed in, restart
the application, and open Printer accounts. It should not restore that session.

Flashforge cloud wireless job submission from the new account panel is not
connected in this revision. Existing Orca LAN workflows are unchanged by the
account integration and still need regression testing. Unified printer selection
and firmware notices are later revisions. Full Bambu
Studio and Flashforge feature parity is not claimed by this preview.

Each revision currently has its own data_dir. The Flashforge system credential
key includes that data directory's path, so another revision or a moved portable
folder may require another sign-in or preset setup. The token is stored in the
system credential store, rather than in the release folder. Existing installed
vendor applications retain their own settings. The vendor networking DLL is loaded from the installed application and
is not redistributed with this revision.
